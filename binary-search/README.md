# Binary Search

| Problem | Pattern | Key Idea |
|---|---|---------------------------------------------------------------------------------------------------------------|
| [Binary Search](https://leetcode.com/problems/binary-search/) | Binary Search | 🟢 Easy • ⏱ 10 min<br>**Approach:**<br>Classic binary search on a sorted array — maintain `low`/`high` bounds, compare the midpoint to the target, and shrink the search space by half each iteration until found or the bounds cross.<br>**Complexity:**<br>Time: O(log n) · Space: O(1) |
| [Search Insert Position](https://leetcode.com/problems/search-insert-position/description/) | Binary Search | 🟢 Easy • ⏱ 10 min<br>**Approach:**<br>Same logic as lower bound — binary search for the first index whose value is `>= target`; if no such element exists, that index equals `n`, the correct insert position.<br>**Complexity:**<br>Time: O(log n) · Space: O(1) |
| [Find First and Last Position of Element in Sorted Array](https://leetcode.com/problems/find-first-and-last-position-of-element-in-sorted-array/description/) | Binary Search | 🟡 Medium • ⏱ 20 min<br>**Approach:**<br>Two binary searches — a lower bound to find the first index `>= target` and an upper bound to find the first index `> target`; if the lower bound doesn't actually equal the target, it's absent.<br>**Complexity:**<br>Time: O(log n) · Space: O(1) |
| [Search in Rotated Sorted Array](https://leetcode.com/problems/search-in-rotated-sorted-array/description/) | Binary Search | 🟡 Medium • ⏱ 20 min<br>**Approach:**<br>Modified binary search — at each step, one half (low to mid, or mid to high) is guaranteed sorted; check if the target lies within that sorted half's range to decide which side to search next.<br>**Complexity:**<br>Time: O(log n) · Space: O(1) |
| [Search in Rotated Sorted Array II](https://leetcode.com/problems/search-in-rotated-sorted-array-ii/description/) | Binary Search | 🟡 Medium • ⏱ 20 min<br>**Approach:**<br>Same modified binary search as the unique-elements version, but with duplicates the sorted-half check can break — when `nums[low] == nums[mid] == nums[high]`, shrink both ends by one and retry.<br>**Complexity:**<br>Time: O(log n) avg, O(n) worst · Space: O(1) |
| [Find Minimum in Rotated Sorted Array](https://leetcode.com/problems/find-minimum-in-rotated-sorted-array/description/) | Binary Search | 🟡 Medium • ⏱ 20 min<br>**Approach:**<br>Modified binary search — at each step, whichever half is sorted has its leftmost value as a minimum candidate; track the smallest candidate seen while discarding the sorted half each iteration.<br>**Complexity:**<br>Time: O(log n) · Space: O(1) |
| [Find Minimum in Rotated Sorted Array II](https://leetcode.com/problems/find-minimum-in-rotated-sorted-array-ii/description/) | Binary Search | 🔴 Hard • ⏱ 25 min<br>**Approach:**<br>Same modified binary search as the unique-elements version, but when `nums[low] == nums[mid] == nums[high]` the sorted half can't be determined — record `nums[low]` as a candidate and shrink both ends by one instead.<br>**Complexity:**<br>Time: O(log n) avg, O(n) worst · Space: O(1) |
| [Single Element in a Sorted Array](https://leetcode.com/problems/single-element-in-a-sorted-array/description/) | Binary Search | 🟡 Medium • ⏱ 20 min<br>**Approach:**<br>Binary search on index parity — before the unique element every pair starts at an even index, after it every pair starts at an odd index; check `nums[mid]` against its neighbor to decide which half breaks the pattern.<br>**Complexity:**<br>Time: O(log n) · Space: O(1) |
| [Find Peak Element](https://leetcode.com/problems/find-peak-element/description/) | Binary Search | 🟡 Medium • ⏱ 20 min<br>**Approach:**<br>Binary search on slope — if `nums[mid] > nums[mid-1]` the array is rising into mid, so a peak lies to the right (inclusive of mid); otherwise it's falling and a peak lies to the left.<br>**Complexity:**<br>Time: O(log n) · Space: O(1) |
| [Find a Peak Element II](https://leetcode.com/problems/find-a-peak-element-ii/description/) | Binary Search | 🟡 Medium • ⏱ 30 min<br>**Approach:**<br>Binary search over columns — for each candidate middle column, find its row-wise maximum, then compare that cell against its left/right neighbors to decide whether it's a peak or which half of columns to search next.<br>**Complexity:**<br>Time: O(n · log m) · Space: O(1) |
| [Koko Eating Bananas](https://leetcode.com/problems/koko-eating-bananas/description/) | Binary Search on Answer | 🟡 Medium • ⏱ 25 min<br>**Approach:**<br>Binary search on the eating speed itself — for a candidate speed, compute total hours needed across all piles; if that's within `h`, try a slower speed, otherwise speed up.<br>**Complexity:**<br>Time: O(n log m) · Space: O(1) |
| [Minimum Number of Days to Make m Bouquets](https://leetcode.com/problems/minimum-number-of-days-to-make-m-bouquets/description/) | Binary Search on Answer | 🟡 Medium • ⏱ 25 min<br>**Approach:**<br>Binary search on the day itself — for a candidate day, scan bloomDay counting runs of consecutive bloomed flowers to see how many groups of `k` (bouquets) can be formed; feasible days shrink the upper bound, infeasible ones raise the lower bound.<br>**Complexity:**<br>Time: O(n log(max−min)) · Space: O(1) |
| [Find the Smallest Divisor Given a Threshold](https://leetcode.com/problems/find-the-smallest-divisor-given-a-threshold/description/) | Binary Search on Answer | 🟡 Medium • ⏱ 20 min<br>**Approach:**<br>Binary search on the divisor itself — for a candidate divisor, sum the ceiling division of each element; if the sum fits within the threshold, try a smaller divisor, otherwise increase it.<br>**Complexity:**<br>Time: O(n log m) · Space: O(1) |
| [Capacity To Ship Packages Within D Days](https://leetcode.com/problems/capacity-to-ship-packages-within-d-days/description/) | Binary Search on Answer | 🟡 Medium • ⏱ 25 min<br>**Approach:**<br>Binary search on ship capacity, bounded by `[max weight, total weight]` — for a candidate capacity, greedily pack days until the load would exceed it; if the days needed fit within `D`, try a smaller capacity, otherwise increase it.<br>**Complexity:**<br>Time: O(n log(sum−max)) · Space: O(1) |
| [Kth Missing Positive Number](https://leetcode.com/problems/kth-missing-positive-number/description/) | Binary Search | 🟢 Easy • ⏱ 15 min<br>**Approach:**<br>Binary search on index — at `arr[mid]`, the count of missing positives so far is `arr[mid] - (mid + 1)`; if that's less than `k`, the answer lies to the right, otherwise to the left. The final answer is `low + k`.<br>**Complexity:**<br>Time: O(log n) · Space: O(1) |
| [Book Allocation Problem](https://takeuforward.org/plus/dsa/problems/book-allocation-problem?source=strivers-a2z-dsa-track) | Binary Search on Answer | 🟡 Medium • ⏱ 25 min<br>**Approach:**<br>Binary search on max pages per student, bounded by `[max pages, total pages]` — for a candidate limit, greedily assign books until a student would exceed it; if the students needed fit within `m`, try a smaller limit, otherwise increase it.<br>**Complexity:**<br>Time: O(n log(sum−max)) · Space: O(1) |
